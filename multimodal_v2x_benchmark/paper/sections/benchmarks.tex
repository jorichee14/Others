\section{Benchmark Tasks and Baselines}
\label{sec:benchmarks}

The benchmark poses five tasks on the dataset, all of them collaborative: in
each, an \emph{ego} agent must produce an output in its own coordinate frame
that it could not produce as well alone, given messages from the other agents
in the same scene. Tasks differ in what the output is (geometry, boxes, pose,
identity) and in which modalities may be used to produce it.

Three properties organise the section. First, every task is reported against a
\textbf{single-agent reference} computed from the ego's own sensors with all
messages withheld; the collaborative number is meaningful only next to it.
Second, baselines are reported in two blocks --- \textbf{LiDAR-only} methods
and \textbf{multi-modal} methods that also consume RGB-D or radar --- and the
blocks are never merged into one ranking, because they have different input
budgets and mixing them hides whether a gain comes from collaboration or from
an extra sensor. Third, every baseline is tagged by \textbf{origin}: indoor
[I], outdoor [O], or simulation-only [S].

All results here are obtained under an \textbf{idealised channel}: messages
arrive complete, in order, with zero delay. Evaluation under logged link
conditions is a separate study (\S\ref{sec:outlook}).

\subsection{Setting and Sensor Suite}
\label{sec:bench:setting}

The platform is an \textbf{indoor} multi-agent testbed. Each agent carries:

\begin{itemize}
  \item \textbf{RGB-D camera} --- registered colour and \emph{measured} depth.
        This is not the same input as the monocular rigs that outdoor
        camera-based collaborative methods assume: depth is observed, not
        predicted, so the depth-distribution stage of a lift-splat frontend is
        supervised or replaced outright. Every camera-branch baseline below is
        specified in both variants (predicted depth / measured depth) so the
        contribution of measured depth is separable.
  \item \textbf{3D LiDAR} --- the reference geometry sensor and the input to
        the LiDAR-only cohort.
  \item \textbf{TI IWR6843 mmWave radar} --- a 60--64\,GHz short-range module
        producing a \emph{sparse} point cloud (order $10^1$--$10^2$ points per
        frame) plus range--Doppler. It is not an automotive 4D imaging radar,
        so outdoor radar-fusion methods cannot be run as published; the
        adaptation is stated per method in \S\ref{sec:bench:radar}.
  \item \textbf{Radio-link measurements} (CSI/RSSI) --- required by the CSI
        sub-protocol of T3 and by T5. These come from the communication radios,
        not from a perception sensor.
        \todo{Confirm a CSI/RSSI logging path exists on the testbed radios and
        state the chipset, bandwidth, and per-packet logging rate; if it does
        not, drop the CSI sub-protocol of T3 and re-scope T5 to RSSI and packet
        metadata only.}
\end{itemize}

The indoor setting is not a cosmetic difference for the baselines. Outdoor
collaborative detectors are parameterised for $\sim$100\,m ranges, $\sim$4\,m
objects, and 0.4\,m voxels; indoors the objects are smaller than one outdoor
voxel. Every outdoor-origin baseline is therefore re-parameterised (detection
range, voxel size, anchor priors, communication range) and the re-parameterisation
is reported with the method, so an outdoor method that underperforms is not
mistaken for a method that was mis-tuned.

\subsection{Notation}
\label{sec:bench:notation}

A scene at time $t$ contains agents $\mathcal{A}_t$ with a designated ego
$e \in \mathcal{A}_t$. Agent $i$ observes a LiDAR sweep $P^i_t$, an RGB-D pair
$(I^i_t, D^i_t)$, a radar return $R^i_t$ (sparse point cloud and
range--Doppler), and link state $H^i_t$ (CSI/RSSI), with pose
$T^i_t \in SE(3)$ in the shared frame. A collaborative method is a map
\begin{equation}
  \hat{y}^e_t \;=\; F\Bigl(S^e_t,\; \bigl\{\,m^{i \to e}_t \,\bigr\}_{i \in \mathcal{A}_t \setminus \{e\}}\Bigr),
  \qquad
  m^{i \to e}_t \;=\; G\bigl(S^i_t,\, T^i_t,\, T^e_t\bigr),
\end{equation}
where $S^i_t$ is the subset of modalities the method admits, $G$ is its
encoder, and $m^{i \to e}_t$ is the message, whose size in bits per frame is
measured and reported for every method. Setting $\mathcal{A}_t = \{e\}$ gives
the single-agent reference $\hat{y}^{e,\mathrm{solo}}_t$.

\subsection{Task Definitions}
\label{sec:bench:tasks}

\paragraph{T1 --- Cooperative point cloud reconstruction.}
\emph{Input:} ego observation, messages from all collaborators, relative poses.
\emph{Output:} a point set $\hat{Q}^e_t \subset \mathbb{R}^3$ in the ego frame
over a fixed evaluation volume $V$, optionally with per-point confidence.
\emph{Ground truth:} the union of all agents' sweeps in the window, registered
into the ego frame with surveyed poses and voxel-deduplicated at resolution
$\rho$, restricted to $V$. \emph{Why collaborative:} the target is geometry the
ego cannot see, so the single-agent reference is bounded away from ground truth
by construction; the task measures how much of that gap a method recovers.

\paragraph{T2 --- Cooperative 3D object detection.}
\emph{Input:} as T1. \emph{Output:} oriented 3D boxes
$\{(x,y,z,l,w,h,\theta,c,s)\}$ in the ego frame. \emph{Ground truth:} the union
of all agents' annotations in the ego frame, filtered to objects observed by at
least one agent within range --- the \emph{same} ground truth scores the
collaborative and single-agent runs, so the reference is scored on objects the
ego alone cannot see.

\paragraph{T3 --- Cross-modal localisation.}
\emph{Input:} one query observation from a single modality --- RGB-D frame,
radar return, or CSI snapshot --- plus a reference representation (the ego's
LiDAR BEV, or the prior map). \emph{Output:} 3-DoF pose $(x, y, \psi)$ in the
shared frame for the map-referenced sub-protocol, relative pose
$\hat{T}^{i \to e}_t$ for the ego-referenced one. \emph{Why collaborative:}
relative pose is the input every fusion operator in T1, T2, and T4 depends on;
this task measures the quality of that input in isolation, per modality,
instead of assuming ground-truth extrinsics.

evaluation.}

\paragraph{T4 --- Communication-efficient collaborative perception.}
\emph{Input:} as T2, plus a bit budget $B$ per frame per link.
\emph{Output:} the T2 output produced under $|m^{i \to e}_t| \leq B$, with the
measured message size. A method is characterised by its \textbf{operating
curve} over $B$, from the late-fusion regime (box lists) to the early-fusion
regime (raw points). \emph{Why separate from T2:} T2 lets each method spend
what it natively spends, so its ranking is partly a bandwidth ranking; T4 puts
the cohort on a common budget axis.
\todo{Fix the budget grid and the accounting rule (payload only vs.\ payload
plus pose/metadata header).}

\paragraph{T5 --- Agent fingerprinting.}
\emph{Input:} a window of $W$ PHY-layer observations from one transmitter
(CSI magnitude/phase, RSSI, per-packet metadata). \emph{Output:} an identity
label over $N$ enrolled agents with an open-set reject option.
\emph{Why in a perception benchmark:} fusion operators weight messages by
claimed identity and pose; fingerprinting establishes how well identity can be
recovered from the physical layer alone, independent of what the message claims
about itself.

\subsection{Splits and Metrics}
\label{sec:bench:splits}

\paragraph{Protocols.}
\emph{Within-environment (WE)}: same rooms in train and test, split by disjoint
time segments with a guard interval $\Delta$ so no test frame shares a temporal
neighbourhood with a training frame. \emph{Leave-one-environment-out (LOEO)}:
train on all rooms but one, test on the held-out room, repeated over rooms;
report the mean over folds with per-fold numbers in the appendix. LOEO is the
headline protocol --- WE measures fit, LOEO measures transfer, and indoor scenes
differ enough room-to-room that the gap is the interesting quantity.
\todo{Enumerate the environments, frame counts per split, $\Delta$, and the
evaluation frame stride.}

\paragraph{Metrics.}
\begin{itemize}
  \item \textbf{T1:} symmetric Chamfer distance (m) and F-score at
        $\{0.02, 0.05, 0.10\}$\,m (indoor-scale thresholds) inside $V$; plus
        \emph{coverage of the ego-occluded region} --- F-score restricted to the
        volume the ego alone does not observe.
  \item \textbf{T2:} AP at IoU $0.5$ and $0.7$ (BEV and 3D), overall and split
        into ego-visible and ego-occluded zones.
  \item \textbf{T3:} median and p90 position (m) and heading (deg) error;
        recall at $\{0.1, 0.25, 0.5\}$\,m for the retrieval-style RGB-D and CSI
        sub-protocols; ATE where the sub-protocol is sequential.
  \item \textbf{T4:} AP@0.7 vs.\ measured bits/frame (log axis), summarised by
        area under the curve and by the smallest budget staying within $1$ AP
        point of the unconstrained T2 score.
  \item \textbf{T5:} closed-set accuracy and macro-F1; open-set AUROC and
        TPR@1\%FPR.
\end{itemize}
Every task additionally reports the \textbf{single-agent reference}, the
\textbf{collaboration gain}, and \textbf{bits/frame}.

\subsection{Baselines}
\label{sec:bench:baselines}

Baselines are grouped by the modalities they consume and ordered by fusion
stage within each group --- \emph{early} (raw measurements), \emph{intermediate}
(learned features), \emph{late} (task outputs) --- because stage determines both
message size and where a collaborator's evidence enters the computation. All
detectors in the LiDAR-only cohort share one backbone, so differences are
attributable to the fusion operator rather than the detector. Origin tags:
[I]~indoor, [O]~outdoor, [S]~simulation-only.

\subsubsection{Single-agent references}
\label{sec:bench:solo}
\begin{itemize}
  \item \textbf{No-Comm LiDAR} --- the shared backbone on the ego sweep alone.
        The floor for the LiDAR-only cohort and for T1/T2.
  \item \textbf{No-Comm RGB-D} --- single-agent detection from the ego RGB-D
        stream; the floor for the camera branch.
  \item \textbf{No-Comm radar} --- single-agent detection from the ego IWR6843
        return; expected to be weak, and reported precisely because it bounds
        what the radar branch can contribute.
  \item \textbf{Single-sweep accumulation} --- the ego's own sweeps integrated
        over the window, as the T1 floor.
\end{itemize}

\subsubsection{LiDAR-only collaborative methods}
\label{sec:bench:lidar}
The V2X lineage below is outdoor by origin; all of it is re-parameterised for
indoor ranges (\S\ref{sec:bench:setting}).
\begin{itemize}
  \item \textbf{Early fusion (Cooper)} \cite{cooper} [O] --- transmit raw
        points, detect once over the union. Information upper bound, bandwidth
        upper bound.
  \item \textbf{Late fusion} [O/I] --- transmit boxes, merge by NMS. Bandwidth
        lower bound.
  \item \textbf{AttFuse (OPV2V)} \cite{opv2v} [O] --- per-cell single-head
        self-attention over aligned BEV features.
  \item \textbf{F-Cooper} \cite{fcooper} [O] --- element-wise maximum
        ("maxout") over aligned feature maps; no capacity to discount a
        contributor.
  \item \textbf{V2VNet} \cite{v2vnet} [O] --- spatially-aware GNN with a
        differentiable warp of neighbour features into the receiver frame.
  \item \textbf{DiscoNet} \cite{disconet} [O/S] --- distillation from an
        early-fusion teacher with matrix-valued edge weights.
  \item \textbf{V2X-ViT} \cite{v2xvit} [O] --- heterogeneous multi-agent
        transformer with agent-type and delay-aware attention.
  \item \textbf{CoBEVT} \cite{cobevt} [O] --- fused axial attention (FAX) over
        the stacked multi-agent BEV tensor; typically the strongest
        clean-channel baseline, and the natural cross-codebase calibration
        bridge because it is implemented in several frameworks.
  \item \textbf{CoAlign} \cite{coalign} [O] --- agent-object pose-graph
        optimisation before multi-scale attention-with-warp; the only baseline
        with an explicit alignment defence, and therefore the one to beat in the
        estimated-pose ablation.
  \item \textbf{Where2comm} \cite{where2comm} [O] --- spatial confidence maps
        select which BEV regions to transmit; exposes a bandwidth knob, so it is
        also a T4 baseline.
  \item \textbf{When2com / Who2com} \cite{when2com,who2com} [S] --- learned
        handshake deciding \emph{when} and \emph{with whom} to communicate;
        originally multi-agent RGB-D scene understanding in simulation rather
        than automotive, which makes it one of the few non-automotive priors in
        the cohort.
  \item \textbf{How2comm / CodeFilling} \cite{how2comm,codefilling} [O]
        \emph{(optional, efficiency-oriented)} --- pragmatic message selection
        and codebook-based message compression; include if the T4 curve needs
        stronger competition at low budgets.
  \item \textbf{HEAL} \cite{heal} [O] --- open heterogeneous collaborative
        perception framework; included both as a method and as the codebase
        whose lineage the indoor baselines follow.
  \item \textbf{InCoP} \cite{incop} [I] --- \emph{indoor} collaborative
        perception benchmark and method (HEAL/OpenCOOD lineage), with its CGRF
        fusion variant. The only baseline in the cohort designed for indoor
        multi-agent geometry, and therefore the reference point for whether the
        outdoor lineage transfers at all.
\end{itemize}

\subsubsection{Radar baselines and the IWR6843 adaptation}
\label{sec:bench:radar}
Published cooperative radar work assumes 4D imaging radar with orders of
magnitude more returns per frame than the IWR6843 provides. The cohort is
therefore split into ported-with-caveat and native-sparse methods:
\begin{itemize}
  \item \textbf{V2X-R} \cite{v2xr} [O] --- LiDAR${+}$4D-radar cooperative
        detection with diffusion-based radar denoising. Portable only if the
        sparse indoor returns are accumulated over a window; report the
        accumulation length, and report the method as adapted.
  \item \textbf{RCooper} \cite{rcooper} [O] --- real roadside cooperative
        perception; a data/protocol reference for multi-view cooperation rather
        than a drop-in indoor method.
  \item \textbf{Classical mmWave pipeline} [I] --- CFAR detection, DBSCAN
        clustering, and constant-velocity tracking, as shipped by the sensor
        vendor's demo stack. Weak but honest, and the correct floor for the
        radar branch.
  \item \textbf{milliEgo} \cite{milliego} [I] --- deep mmWave${+}$IMU odometry
        on a single-chip radar; the indoor precedent that the IWR6843 class of
        sensor supports pose estimation, used as a T3 radar baseline.
  \item \textbf{RadarHD} \cite{radarhd} [I] --- single-chip mmWave to
        LiDAR-like point cloud super-resolution; used as a T1 radar
        reconstruction baseline and as an optional densifier in front of the
        cooperative operators.
  \item \textbf{milliMap} \cite{millimap} [I] --- indoor mmWave mapping with a
        single-chip radar; the mapping-side indoor precedent for T1.
\end{itemize}

\subsubsection{Task-specific baselines (T1, T3, T5)}
\label{sec:bench:taskspecific}

\paragraph{T1 --- reconstruction.}

\paragraph{T3 --- localisation and registration.}

\emph{Multi-robot collaborative SLAM} (system-level references for T1${+}$T3

\paragraph{T5 --- fingerprinting.}

\subsection{Ablations}
\label{sec:bench:ablations}

\begin{enumerate}
  \item \textbf{Modality on/off} (multi-modal cohort): each of RGB, depth, and
        radar removed in turn at fixed architecture and agent count.
  \item \textbf{Measured vs.\ predicted depth}: the RGB-D channel substituted
        for the lift-splat depth distribution, isolating what the depth sensor
        buys over monocular depth prediction.
  \item \textbf{Number of cooperating agents}: $|\mathcal{A}_t| = 1, 2, 3, \dots$
        as a curve per cohort; establishes where the gain saturates indoors.
  \item \textbf{Fusion stage at matched bandwidth}: early / intermediate / late
        at equal bits/frame rather than at native sizes --- the only comparison
        in which stage is the sole variable.
  \item \textbf{Pose source}: ground-truth extrinsics vs.\ poses estimated by
        the T3 baselines; quantifies how much reported accuracy is contingent on
        perfect alignment, and is where CoAlign should separate from the rest.
  \item \textbf{Indoor re-parameterisation}: published outdoor configuration
        vs.\ indoor-tuned configuration, on one representative method per
        family --- evidence that outdoor methods were given a fair chance.
  \item \textbf{Geometry}: performance vs.\ inter-agent distance and vs.\
        relative viewpoint angle.
